## Description

Allow the operator to create a new backlog item directly from the backlog app, without touching the terminal or a text editor. The app copies `_template.md`, assigns the next available ID, and opens the new ticket for immediate editing.

## Acceptance Criteria

- [ ] A "New Item" button is visible on the main board (e.g. top toolbar).
- [ ] Clicking it determines the next available ID by scanning existing filenames in `../items/` and `../archive/` (highest `{NNN}` + 1, never reusing a number).
- [ ] A new `.md` file is created in `../items/` based on `../_template.md`, with the assigned ID pre-filled in the frontmatter.
- [ ] The app opens an edit view (or inline form) for the new ticket immediately after creation, with `id` and `status: OPEN` pre-set and all other fields editable.
- [ ] The new card appears on the board in the `OPEN` column without requiring a manual reload.
- [ ] If file creation fails (e.g. permissions error), the app shows a clear error message and does not leave a partial file on disk.

## Notes

ID assignment must be collision-safe: scan both `items/` and `archive/` to find the true highest number. Do not rely on file count alone — gaps from canceled/deleted tickets would cause ID reuse.
