## Description

The application should support dakr and light mode, but both modes have to have internally consistent color schemes so that contrast is ensured on each UI element. Currently this isn't so. In the default mode the app starts in, for example text fields are white with white text with the background changing to grey and making it readable only on focus.

Check the entire app and ensure contrast.

## Acceptance Criteria

- [x] All hardcoded hex colours replaced with `Palette` tokens from Slint's `std-widgets.slint` so the UI inherits the system colour scheme automatically.
- [x] Card backgrounds use `Palette.control-background`; card text uses `Palette.foreground`; muted text uses `Palette.control-foreground.transparentize(0.4)`.
- [x] Column backgrounds use `Palette.alternate-background`; column hover state uses `Palette.selection-background`.
- [x] Dialog backgrounds use `Palette.background`; dialog borders use `Palette.border`.
- [x] `AppButton` disabled/enabled states use palette tokens; primary button retains fixed accent blue (`#2563eb`) and white label.
- [x] Error text retains fixed `#e05252` (semantic red, intentionally invariant).
- [x] App window background uses `Palette.background`.
- [x] The fix applies to both light and dark system appearances without any mode-specific branching in application code.

## Notes

`Palette` is resolved at runtime by Slint's active widget style (Fluent on Windows, Cupertino on macOS, etc.) and correctly reflects the system dark/light mode setting. No Rust changes required — this is a Slint-layer-only fix.
