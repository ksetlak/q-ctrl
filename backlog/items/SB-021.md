## Description

The current `repo_root()` in `main.rs` walks up multiple parent directories from the executable path, which was tied to the debug build layout (`target/debug/`). Per ADR-0002, the distributed binary lives at the repo root. The path logic must be updated to match, and a Justfile must automate the build-and-copy step so the repo-root binary stays current after every build.

## Acceptance Criteria

- [ ] `repo_root()` returns `current_exe().parent()` — one hop only.
- [ ] A `Justfile` exists at the repo root with `build`, `release`, and `run` recipes.
- [ ] `just build` compiles a debug binary and copies it to the repo root as `qctrl`.
- [ ] `just release` compiles a release binary and copies it to the repo root as `qctrl`.
- [ ] `just run` builds (debug) and immediately launches the copied binary from the repo root.
- [ ] `qctrl` and `qctrl.exe` are listed in `.gitignore`.
- [ ] Running the repo-root binary against a Scaffold project correctly loads `backlog/items/`.

## Notes

ADR-0002 records the distribution decision (standalone binary, GitHub Releases).
The Justfile uses `justfile_directory()` as the repo root anchor, so it works regardless of where `just` is invoked from.
