## Description

Read all `.md` files from `backlog/items/` (one level up from the binary's location), parse their YAML frontmatter, and render each ticket as a card in a single scrollable column. This validates the full data pipeline from file to UI before any Kanban layout is added.

## Acceptance Criteria

- [ ] App reads all `.md` files from `../items/` relative to the binary location on startup.
- [ ] YAML frontmatter fields `id`, `title`, `status`, and `priority` are parsed correctly.
- [ ] Each ticket is rendered as a card showing at minimum: `id`, `title`, `status`.
- [ ] Cards are sorted by `order` (ascending), falling back to `id` if `order` is absent.
- [ ] A file that fails to parse (malformed frontmatter) is skipped with a visible error indicator, not a crash.
- [ ] Tested with at least 3 fixture `.md` files covering varied statuses and priorities.

## Notes

Use `gray_matter` or `serde_yaml` for frontmatter parsing — whichever has better Slint/Rust integration examples at the time of implementation. Check crate docs before choosing.
