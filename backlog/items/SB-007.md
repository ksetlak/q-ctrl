## Description

Allow the operator to move a ticket to a different status by dragging its card from one Kanban column and dropping it into another. Dropping writes the new `status` value to the ticket's frontmatter on disk. This makes status transitions a direct manipulation gesture rather than a file edit.

## Acceptance Criteria

- [x] A card being dragged over a different column highlights that column as a valid drop target.
- [x] Dropping the card onto a target column updates the `status` frontmatter field to match that column's status value and writes the change to disk.
- [x] The card disappears from its source column and appears in the target column immediately after the drop, without a full board reload.
- [x] The card's `order` value is set to `0.0` (unset sentinel) when dropped into a new column, placing it at the bottom of the sort order until the operator reorders it manually.
- [x] Dropping a card back onto its own column is a no-op: handled by the same-column reorder path (status unchanged, order recomputed if position changed).
- [ ] A file write failure shows an error notification and leaves the card in its original column. (logged only; visual revert deferred)
- [x] The in-column drop indicator from SB-006 remains functional when dragging within the same column.

## Notes

Status values written to frontmatter must match the canonical uppercase strings defined in backlog/README.md (e.g. `IN_PROGRESS`, `AWAITING_OPERATOR`). The DONE/CANCELED column introduced in SB-008 is a special case handled there; this ticket covers all other standard columns.
