## Description

Q-CTRL uses the folder it was started from as the project root. When that folder has no `backlog/items/`, for example after a double-click in Finder, it currently prints a message and exits, which a user who didn't start it from a terminal never sees. Instead, show a native folder picker so the user can choose a Scaffold project, then continue as if Q-CTRL had been started from that folder. Out of scope: remembering the choice between launches, and switching projects while the app is running.

## Acceptance Criteria

- [ ] Launched from a folder with `backlog/items/`, Q-CTRL opens that project directly and shows no picker.
- [ ] Launched from any other folder, Q-CTRL shows a native folder picker.
- [ ] Choosing a folder with `backlog/items/` opens the board for that project, and all file paths (items, archive, template, `.copier-answers.yml`, debug log) resolve against the chosen folder.
- [ ] Choosing a folder without `backlog/items/` shows a clear message and offers to pick again or quit.
- [ ] Cancelling the picker quits Q-CTRL without an error or a stray log file.
- [ ] Verified on macOS (launched from Finder) and on Linux. Windows is nice to have.

## Notes

Slint has no built-in folder dialog, so this probably needs a crate such as `rfd`. Check it against the rule in `AGENTS.md` about dependencies compiling on macOS and Linux without system libraries. On Linux, `rfd` can use either GTK3 or the desktop portal, and the choice affects what users need installed. If it adds a system dependency, record the decision in an ADR.

A Finder-launched app usually starts with `/` as its working directory, so the "not a project" check must not assume the working directory is something sensible.

Possible follow-up: remember the last project in `~/.config/qctrl/config.toml` (the location `AGENTS.md` reserves for user config) so the picker only appears the first time.

Related: the "Open Questions" section of ADR-0002 records this as the remaining part of project root detection.
