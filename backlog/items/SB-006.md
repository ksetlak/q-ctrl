## Description

Allow the operator to reorder ticket cards within a column by dragging them vertically. Dropping a card between two others assigns it an `order` value between theirs (float midpoint). This is the primary mechanism for expressing priority within a status bucket without editing frontmatter directly.

## Acceptance Criteria

- [x] A card can be picked up by clicking and holding anywhere on its surface.
- [x] A visual drop indicator (line or highlight) appears between cards as the dragged card passes over them.
- [x] Dropping the card writes an updated `order` float value to the ticket's `.md` frontmatter on disk.
- [x] The board re-renders to reflect the new order immediately after the drop, without a full reload.
- [x] Midpoint precision: if two adjacent `order` values are within 0.001 of each other, rebalance all `order` values in the column with even spacing (integers: 1.0, 2.0, 3.0, …) before assigning the new midpoint.
- [ ] A file write failure shows an error notification and reverts the card to its original position. (error is logged; visible toast deferred to a future ticket)
- [x] Reordering does not change any frontmatter field other than `order`.

## Notes

`order` is a float as per ADR-0001 and backlog/README.md. Midpoint assignment (e.g. drop between `order: 2.0` and `order: 3.0` → `order: 2.5`) avoids rewriting sibling files on every drag. Rebalancing is the escape hatch for precision exhaustion and is expected to be rare.
